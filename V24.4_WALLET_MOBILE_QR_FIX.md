# V24.4 Wallet Mobile / QR Fix

This patch is based directly on `BaseQuestMilestones_V24.4_FULL_AUDIT_FINAL.zip`.

- Pins this BOT testnet release to the official Bohr Testnet identity: Chain ID 968, RPC `https://rpc.bohr.life`, explorer `https://scan.bohr.life`, BOT gas token. This prevents stale GitHub Variables from accidentally directing mobile wallets to the legacy Base network.
- Keeps EIP-6963 multi-wallet discovery and exact RDNS matching.
- Fixes the WalletConnect v2 optional namespace so `eth_sendTransaction` and account/chain events are actually requested when using `optionalChains`.
- Keeps the official WalletConnect/AppKit QR modal and enables mobile full-screen mode.
- Passes the target chain/rpc again on each new WalletConnect pairing.
- Detects stale WalletConnect sessions created by older builds and forces a fresh pairing if Chain ID 968 or `eth_sendTransaction` was not approved.
- Hardens mobile chain switching: recognizes nested 4902 errors, adds Bohr Testnet when absent, explicitly switches after add, and waits for delayed mobile `eth_chainId` updates before declaring failure.
- A wallet connection is no longer discarded merely because automatic network switching was not completed; write operations still strictly require Chain ID 968.
- GitHub Pages deployment refuses to publish without `VITE_WALLETCONNECT_PROJECT_ID`, because WalletConnect v2 cannot create a real pairing QR/mobile session without a project ID.
