# Base Quest Milestones V24.4 — Full Audit Report

## Scope
This release is based on the latest V24.3 client and retains the hardened V23 smart contract. The audit covered wallet/provider handling, WalletConnect setup and fallback behavior, gameplay/lives/retry/checkpoint state, anti-cheat/session handling, UI/navigation/responsive structure, static pages, NFT gallery assets, metadata, deployment workflow, and client-side error handling.

## Gameplay / lives / retry
- Losing life 1 or 2 keeps the same active run and does not reset score, elapsed play time, stage, player/world position, verified-run state, or anti-cheat ledger.
- A 1.5-second post-hit damage grace prevents a single collision from consuming multiple lives.
- Losing life 3 ends the run and starts a persistent 3-minute retry lock.
- Retry lock survives page refresh/reopen and cannot be bypassed by Start, Space, tap, jump-start logic, or direct `game.start()`.
- After the lock expires, the restart checkpoint is derived from the highest sequential protocol-minted milestone (`mintedByProtocol`), not from transferable NFT ownership alone.
- Checkpoint score and anti-cheat score ledger are restored together.
- Hidden-tab anti-cheat invalidation now terminates an invalid active run cleanly.

## Wallet / WalletConnect
- Wallet provider discovery uses EIP-6963 first and de-duplicates provider objects.
- RDNS wallet matching is exact; unsafe substring matching was removed.
- Signer refresh clears stale account state when the provider returns no accounts.
- Failed connection attempts roll back provider state and event listeners.
- WalletConnect initialization uses `optionalChains` for BOT Chain and a minimal required transaction namespace, with compatibility methods optional.
- With a valid `VITE_WALLETCONNECT_PROJECT_ID`, the official WalletConnect QR/mobile pairing flow is used.
- Without a Project ID, the previous blocking browser alert is removed. The UI instead exposes a clearly labelled Mobile / QR fallback. This fallback is intentionally not represented as a true WalletConnect pairing QR.
- Mobile-compatible raw EIP-1193 `eth_call` fallback was added for contract reads.
- Progress synchronization refuses to overwrite known progression with partial/unknown data when RPC reads fail.
- Balance text avoids lossy JavaScript Number conversion.

## UI / pages
- Real standalone pages are present for Home, Play, Dashboard, NFT Gallery, XP, Rules, About, Contact, and Community.
- The left drawer navigates to real page files; dead `href="#"` links were removed.
- Mobile jump interception is scoped to the runner canvas so page scrolling/tapping is not hijacked.
- Lives HUD is tied to game state, not a static heart display.
- Start/Jump controls reflect retry lock, active run, mint-preservation, and verified-start state.
- Async wallet/progression UI updates are guarded against stale account responses.
- NFT Gallery uses optimized lazy-loaded WebP previews while original NFT artwork remains unchanged for metadata/mint use.

The client smoke test specifically verifies same-run life continuity, persistent three-minute lockout, input lockout, protocol-mint checkpoint recovery, and hidden-tab anti-cheat recovery.

## Dependency-backed build limitation
The audit environment did not have `node_modules` installed and npm registry access did not complete, so a dependency-backed Vite build and Hardhat compile/test were not claimed as locally executed in this final audit. The repository's GitHub Actions workflows remain configured to install dependencies and execute the build/contract pipeline in CI.
